# Vault Check

**NEAR Intents를 위한 공개·무키(無key) 준비금 점검: 컨트랙트가 사용자에게 빚진 만큼을 실제로 들고 있는가?**

[English](README.md) · [NEAR HACKATHON](https://nearhackathon.com) (2026년 11월) 출품작. 트랙: `open`, `defi`, `security`.

**재생 화면 보기:** [https://lee2017-bit.github.io/near-vault-check/](https://lee2017-bit.github.io/near-vault-check/) (45초, 브라우저에서 바로 재생) · [전체 리포트](https://lee2017-bit.github.io/near-vault-check/report.html)

## 문제

NEAR Intents는 모든 사용자의 예치금을 `intents.near`라는 컨트랙트 하나의 내부 장부(NEP-245 멀티 토큰)로 관리합니다.
실제 토큰은 각 토큰 컨트랙트에 `intents.near`의 잔액으로 들어 있습니다.
따라서 모든 토큰에서 장부는 항상 금고로 담보되어 있어야 합니다.

```
장부(token) = intents.near.mt_supply(token)                          Intents가 전체 사용자에게 빚진 양
금고(token) = <토큰 컨트랙트>.ft_balance_of / mt_balance_of(intents.near)   실제로 들고 있는 양
불변식:       장부 <= 금고
```

2026년 9월 29일부터 10월 1일까지, 입금 알림 처리의 버그로 공격자가 금고에는 한 번도 들어온 적 없는 USDT 380만 달러어치를 장부에 만들어 내고 인출했습니다.
팀의 사후 보고서는 바로 이 차이를 당시 감시하지 않았다고 밝힙니다.

> "NEAR Intents의 내부 시스템은 원 체인과 NEAR 쪽 전체 토큰 잔액의 차이는 감시하고 있었지만, NEAR Intents 전체 사용자 잔액의 합과 Intents 컨트랙트의 토큰 잔액 사이의 차이는 감시하지 않았다." (번역, [사후 보고서 원문, 2026-10-16](https://x.com/AlexAuroraDev/status/2111124226962870770))

이후 팀은 이 점검을 자동 일시정지와 함께 내부에 추가했고, 피해 사용자는 모두 전액 보상받았습니다.
Vault Check는 그 점검의 **독립적이고 공개된** 버전입니다. 키, 자금, 인덱서 없이 누구나 실행할 수 있고, 10월 사고를 공개 체인 데이터로 다시 재생해 이 점검이 언제 울렸을지 보여줍니다.

## 동작 방식

- `vaultcheck/tokens.py`는 `intents.near.mt_tokens`(87,000개 이상, 대부분 NFT)를 훑어 대체 가능 토큰만 남깁니다: `nep141:<컨트랙트>`와 `nep245:<컨트랙트>:<내부 id>`.
- `vaultcheck/scan.py`는 같은 블록에서 양쪽을 읽습니다: `intents.near`의 `mt_batch_supply`(호출당 50개), 각 NEP-141 컨트랙트의 `ft_balance_of(intents.near)`, 각 NEP-245 컨트랙트의 `mt_batch_balance_of(intents.near, ...)`.
- `vaultcheck/alarm.py`는 토큰마다 상태를 매깁니다: `backed`(장부 <= 금고), `standing`(예전부터 있었고 커지지 않는 차이), `drift`(커지고 있지만 기준 미만), `ALARM`(기준선 이후 미담보 차이가 $1,000 이상 커짐), `unverifiable`(한쪽을 읽을 수 없음).
- `vaultcheck/reproduce.py`는 `data/`만으로 모든 숫자를 오프라인에서 다시 계산하고, `vaultcheck/report.py`와 `vaultcheck/demo.py`가 단일 파일 HTML 리포트와 재생 화면을 만듭니다.
- `vaultcheck/rpc.py`는 작은 JSON-RPC 클라이언트입니다: 아카이브 `block_id` 조회, 공용 호출 속도 제한, 429 재시도, 긴 스캔을 이어서 할 수 있는 디스크 캐시.

### 사용한 NEAR 기능

| 기능 | 쓰인 곳 |
| --- | --- |
| `intents.near`의 NEP-245 `mt_supply`, `mt_batch_supply`, `mt_tokens` | 장부 쪽, 토큰 목록 |
| NEP-141 `ft_balance_of`, NEP-245 `mt_batch_balance_of` / `mt_balance_of` | 금고 쪽 |
| 고정 `block_id`의 아카이브 조회 호출 | 과거 재생, 재현 가능한 스냅숏 |
| `intents.near`의 `pa_is_paused({"key":"ALL"})` | 체인상 일시정지가 사후 보고서와 맞는지 확인 |
| 이름 있는 계정과 컨트랙트가 보유한 잔액 | 키 없이, 트랜잭션 없이 점검 전체가 가능한 이유 |

## 단순 비교로는 부족한 이유: 오탐 레지스트리

기준선 없이 `장부 <= 금고`만 보면 사고와 무관한 토큰들이 늘 빨간불을 켭니다. 그런 토큰은 `data/registry.json`에서 사람이 직접 이유를 분류하고, 숨기지 않고 `standing`이나 `drift`로 보여줍니다. 아래는 생성된 원본입니다(영문).

## 한계

- 잡아내는 실패 유형은 하나입니다: 장부가 금고보다 많이 빚진 상태. 2026년 Rhea Lend 손실(오라클 조작)이나 SWEAT Foundation 손실(인출 로직 결함)은 잡지 **못했을** 것이며, 그런 사고에는 다른 통제가 필요합니다.
- 감시 장치이지 차단 장치가 아닙니다. 돈이 새기 시작한 뒤에 경보를 울립니다. 가치는 탐지까지 걸리는 시간에 있습니다.
- NFT id(`nep171`)는 범위 밖입니다. 토큰 목록은 스냅숏(`data/universe.json`)이므로 나중에 추가된 토큰은 갱신해야 합니다.
- 달러 환산은 공개 Intents 토큰 API에서 받아 커밋한 가격 스냅숏을 씁니다. 가격이 없는 토큰은 상대 규칙(차이가 장부의 1% 커지면 경보)을 씁니다.
- 토큰별 합계만 공개합니다. 계정별 잔액이나 공격자 주소는 공개하지 않습니다.
